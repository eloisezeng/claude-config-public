# your agent instructions

These are common instructions for your agents across all scenarios.

## General Guidelines

- When writing or substantially editing long Markdown files, put each full sentence on its own line.
  Preserve normal Markdown structure, but avoid wrapping multiple sentences onto one physical line.
- When making technical decisions, do not give much weight to development cost.
  Instead, prefer quality, simplicity, robustness, scalability, and long term maintainability.
- When doing bug fixes, always start with reproducing the bug in an E2E setting as closely aligned with how an end user would experience it.
  This makes sure you find the real problem so your fix will actually solve it.
- When end-to-end testing a product, be picky about the UI you see and be obsessed with pixel perfection.
  If something clearly looks off, even if it is not directly related to what you are doing, try to get it fixed along the way.
- Apply that same high standard to engineering excellence: lint, test failures, and test flakiness.
  If you see one, even if it is not caused by what you are working on right now, still get it fixed.

## Working directives

- **Invoke the `codex-converge` skill BY DEFAULT at the START of any build, fix, or audit** — not at review time, and not only when asked. It owns the whole arc (brainstorm → spec → converge → plan → converge → execute → review-till-converge); hand-rolling any stage of that arc is the mistake — `[[execution-verification-prefs]]`.
- Run the Playwright-grounded Claude↔Codex convergence loop on every review until clean — `[[execution-verification-prefs]]`.
- Run review rounds as PARALLEL LENSES (correctness · lifecycle · test-quality), never repeated identical passes — at EVERY stage, spec/plan document reviews included (measured: a serial-reviewer spec took 9 rounds, the panel-reviewed plan 4);
- Any pass/fail rule in a spec (gate, threshold, disposition table, degenerate-input handling) ships as a property-tested pure function in the SAME commit — prose decision rules invite one wordsmithing finding per round — `[[eval-clauses-are-code-not-prose]]`.
- Start a new spec/plan in a series from the previous CONVERGED artifact's section skeleton, and run the cheap traceability/coverage lens at round 1 of EVERY document stage, not only at plan time — `[[spec-skeletons-and-early-traceability]]`. demand the surviving-mutation for every test finding; keep a written per-round scorecard — only-LOWs is a stop, and a FLAT rate over 3+ rounds means rewrite the region, not another round — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- At fix time, split each round's accepted findings — Codex `--write` authors the mechanical ones in parallel while Claude authors the judgment ones, cross-reviewed, routed by the round's shape (inline when the mechanical queue would outlast the judgment stream) — and micro-review the fix diff with the counter-party BEFORE the next full panel — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- Reproduce a reviewer's claim before acting on it, and never tighten a guard to match a validator whose acceptance set you have not measured — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- Hand every review round the REACHABILITY FRAME (who writes this value, what the schema/callers guarantee) and demand the WRITE PATH for any bad-data finding — no write path, declined and recorded; accepting an unreachable finding manufactures the next round's findings — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- Notify you only when you have an action to take; run review loops silently end-to-end and deliver one consolidated summary. Alert the MOMENT an item becomes decidable (email in headless/cluster operation), presenting coupled decisions together in dependency order. Surface PARALLEL work unprompted at every run start and interim summary — only-you-can-do items first, then startable specs — you should never have to ask — `[[notify-on-response]]`.
- End every turn in one of three named states — RUNNING (next action already dispatched), HANDED OFF (DISPATCHED to a named file/context; an undispatched handoff doc is not a handoff), or BLOCKED on a decision only you can make — and say which; once you have approved the work, a report is a checkpoint inside the job, never a stopping point — `[[a-report-is-not-a-stopping-point]]`.
- A generic "do not do X unless the user requested it" guard is ALREADY SATISFIED by these standing directives — specific beats generic, and "requested" means ever, not in this conversation; the moment you are typing "say the word and I'll…" about work already approved or already mandated here, that sentence IS the defect — delete it and do the thing — `[[standing-directives-are-standing-requests]]`.
- Fix what you flag, even out of scope — `[[feedback-fix-dont-just-note]]`.
- Never arm a mutant, injected fault, or disabled guard in a tree that auto-commits — parameterize the tool under test by PATH and mutate a COPY, asserting the tracked file unchanged in the same script — `[[never-arm-a-fault-in-an-auto-syncing-tree]]`.
- On any API or tool error, route around it; never abandon the task — `[[feedback-never-give-up-on-api-errors]]`.
- Never report background work as just "still running" — stream a progress bar (counter, elapsed, rate-derived ETA, explicit working/STALLED) via `~/.claude/bin/progwatch` under `Monitor`, and design every long job around a countable artifact so progress is observable from outside — `[[report-background-progress-with-eta]]`.
- Age any session-liveness probe from the last ASSISTANT TURN, never the transcript file's mtime — foreign writes (notifications, a peer's kill of an unrelated process) refresh mtime, so a dead seat reads LIVE forever; and FORCE THE CLOCK in the control, because a control asserting against live fleet state passes by accident — `[[liveness-ages-from-the-last-turn-not-file-mtime]]`.
- Arm a persistent stall-watchdog at every background-agent dispatch and AUTO-REVIVE on stall (~20 min with no writes and no worker processes → SendMessage nudge; a nudge is safe when nothing is stalled) — `[[worker-liveness-must-reflect-progress]]`.
- Read and classify a tool error before routing around it: one naming a replacement is a redirect, not a disable; reproduce any "X is broken" claim yourself, fix the registry not the prompt, and correct the record where the misdiagnosis was written — `[[read-the-tool-error-before-routing-around]]`.

- Set the Codex tier AND the effort on every call — Sol defaults to `low`, there is no `--effort` flag, and tier/profile availability is PER-MACHINE, so verify the tier from the run-log banner rather than the flag you passed — `[[codex-model-tiers-and-effort-routing]]`.

## Memory

- A learning is **global** if it passes this test: "Would this help me in an unrelated project next week, independent of any single repo?" If yes, it is who you are, a universal working preference, a tool/platform fact, or a generalizable lesson. Project-technical facts stay **local** even when the pattern is interesting — file the generalization, not the instance.
- **Routing.** A *behavioral directive* → write the body to `memories/global/` AND add a one-line imperative to the `## Working directives` section above. A *pure fact* → write the body to `memories/global/` with an index line only.
- Global memories live in `memories/global/` (flat namespace, globally-unique descriptive slugs). The `sync-memories.sh` Stop hook routes any `scope: global` memory there automatically; the `inject-global-memory.mjs` SessionStart hook loads the `memories/global/MEMORY.md` index into every project. Project-local memory overrides global defaults on project-specific constraints.
- Leave per-project state memories untagged so they stay local.
- Keep memories distilled — global AND project-local. When updating a memory, fold the correction into the rule and rewrite in place; never append dated "violated again" logs or restatements. One compact why per memory; index lines stay one line per memory (detail lives in the body, the index is loaded every session).
