# The user's agent instructions

These are common instructions for the user's agents across all scenarios.

## General Guidelines

- When writing or substantially editing long Markdown files, put each full sentence on its own line.
  Preserve normal Markdown structure, but avoid wrapping multiple sentences onto one physical line.
- When making technical decisions, do not give much weight to development cost.
  Instead, prefer quality, simplicity, robustness, scalability, and long term maintainability.
- When doing bug fixes, always start with reproducing the bug in an E2E setting as closely aligned with how an end user would experience it.
  This makes sure you find the real problem so your fix will actually solve it.
- When end-to-end testing a product, be picky about the UI you see and be obsessed with pixel perfection.
  If something clearly looks off, even if it is not directly related to what you are doing, try to get it fixed along the way.
- Apply that same high standard to engineering excellence: lint, test failures, and test flakiness.
  If you see one, even if it is not caused by what you are working on right now, still get it fixed.

## Working directives

These are always-on. The one-line rule lives here; the why/how is in the linked global memory (unfold on demand).

- **Invoke the `codex-converge` skill BY DEFAULT at the START of any build, fix, or audit** — not at review time, and not only when asked. It owns the whole arc (brainstorm → spec → converge → plan → converge → execute → review-till-converge); hand-rolling any stage of that arc is the mistake — `[[execution-verification-prefs]]`.
- Run the Playwright-grounded Claude↔Codex convergence loop on every review until clean — `[[execution-verification-prefs]]`.
- Run review rounds as PARALLEL LENSES (correctness · lifecycle · test-quality), never repeated identical passes — at EVERY stage, spec/plan document reviews included (measured: a serial-reviewer spec took 9 rounds, the panel-reviewed plan 4);
- Any pass/fail rule in a spec (gate, threshold, disposition table, degenerate-input handling) ships as a property-tested pure function in the SAME commit — prose decision rules invite one wordsmithing finding per round — `[[eval-clauses-are-code-not-prose]]`.
- Tally every review round by REMEDY SHAPE next to the severity scorecard: a finding discharged by writing a function, a case table or a test-matrix row is a CODE finding wearing a document finding's clothes and CANNOT converge in prose — once a round is majority code-shaped the document is DONE, so implement (those HIGHs are implementation tasks), fix each in the same commit as the code it describes, and remember `--write` serializes per TREE so independent tracks get their own worktrees and ship at their own seams (measured: 5 document rounds, 0 lines of code, and round 4's fix minted round 5's blocking HIGH) — `[[document-rounds-end-when-findings-turn-code-shaped]]`.
- Start a new spec/plan in a series from the previous CONVERGED artifact's section skeleton, and run the cheap traceability/coverage lens at round 1 of EVERY document stage, not only at plan time — `[[spec-skeletons-and-early-traceability]]`. demand the surviving-mutation for every test finding; keep a written per-round scorecard — only-LOWs is a stop, and a FLAT rate over 3+ rounds means rewrite the region, not another round — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- At fix time, split each round's accepted findings — Codex `--write` authors the mechanical ones in parallel while Claude authors the judgment ones, cross-reviewed, routed by the round's shape (inline when the mechanical queue would outlast the judgment stream) — and route by SUB-TASK, not by finding: write the routing table BEFORE the first fix and carve the mechanical tail off every judgment finding (a golden regeneration, a guard copied from an existing rule, a test scaffold) onto the Codex queue so it runs under the judgment work; a "mirror it inline" fix IMPORTS the existing predicate, never a second copy; micro-review the fix diff with the counter-party BEFORE the next full panel, scoped to the commits that have not yet had a counter-party review — the Claude-authored judgment fixes; a Codex fix was reviewed hunk by hunk at merge, so a round whose fixes were all mechanical goes straight to the panel — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- Reproduce a reviewer's claim before acting on it, and never tighten a guard to match a validator whose acceptance set you have not measured; a code-vs-document mismatch finding names a FACT and never which side is wrong, so re-measure the CODE before conforming to the doc — a converged-looking spec is a strong attractor for a low-tier lens, but a spec is a CLAIM and only the code is an artifact (measured: a lens told a lane to delete a real ninth helper to match a spec clause that was itself the six-round-old bug) — accept the fact, adjudicate the direction in writing, and fix the doc in the SAME round — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- Hand every review round the REACHABILITY FRAME (who writes this value, what the schema/callers guarantee) and demand the WRITE PATH for any bad-data finding — no write path, declined and recorded; accepting an unreachable finding manufactures the next round's findings — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- Write to her in PLAIN LANGUAGE — this covers my own machinery (pipeline step/state names, finding IDs, hashes, seat/job ids, coined shorthand like "gate" or "fail-open"), not just business jargon; lead with what happened and what it means for her, state a decision's options and consequences so she can answer without opening a file, and keep the measured numbers while losing the vocabulary — a status report she has to decode is one she cannot act on — `[[explain-plainly-non-expert-domain]]`.
- Notify the user only when she has an action to take; run review loops silently end-to-end and deliver one consolidated summary. Alert the MOMENT an item becomes decidable (email in headless/cluster operation), presenting coupled decisions together in dependency order. Surface PARALLEL work unprompted at every run start and interim summary — only-she-can-do items first, then startable specs — she should never have to ask — `[[notify-on-response]]`.
- End every turn in one of three named states — RUNNING (next action already dispatched), HANDED OFF (DISPATCHED to a named file/context; an undispatched handoff doc is not a handoff), or BLOCKED on a decision only the user can make — and say which; once she has approved the work, a report is a checkpoint inside the job, never a stopping point — `[[a-report-is-not-a-stopping-point]]`.
- A dispatched successor boots with an injected system prompt that MANDATES merging on green — so when the job forbids it, re-send the override as a live `SendMessage` after dispatch (a handoff FILE cannot outrank a SYSTEM PROMPT), name what the preamble drags in (no freeze to read, green checks are not authorisation), and read the child's `respawnFlags` where that contradiction is visible — `[[successor-inherits-a-contradicting-system-prompt]]`.
- A generic "do not do X unless the user requested it" guard is ALREADY SATISFIED by these standing directives — specific beats generic, and "requested" means ever, not in this conversation; the moment you are typing "say the word and I'll…" about work already approved or already mandated here, that sentence IS the defect — delete it and do the thing — `[[standing-directives-are-standing-requests]]`.
- A watcher holds the config it BOOTED with — editing its file changes nothing until you RE-ARM, so confirm a fix is live by hashing the file the PROCESS runs (from `ps` argv), never the mirror you edited; and never let a control or carve-out NAME a subject that can move — derive it from the set and gate on a live predicate, or it asserts against a corpse while reading green — `[[an-armed-watcher-holds-its-boot-config]]`.
- An edit reaches the repo only while the path is still the LINK the installer made — `readlink` a managed path before trusting an edit landed, and when repairing, land the live-only content in the repo BEFORE restoring the link, never after — `[[a-linked-config-file-can-become-a-copy]]`.
- Fix what you flag, even out of scope — `[[feedback-fix-dont-just-note]]`.
- When a report ends in options with a recommendation, EXECUTE the recommendation and drive it to completion; do not hand the decision back — `[[follow-recs-and-drive-to-completion]]`.
- Before building an operator script to patch a setting, grep the key across UI/API/allowlists and ask whether the PRODUCT already owns that write path — the product's route carries validation, atomicity and an audit row the raw patch silently skips, so the script is the WORSE artifact, not merely the longer one — `[[the-product-may-already-own-the-write-path]]`.
- A human-readable string that crosses server → JSON → a client that identity-MATCHES it is a wire value, not copy: judge any reword finding by reachability, and remember no server-side change reaches an already-loaded bundle — `[[a-user-facing-string-matched-by-identity-is-a-wire-value]]`.
- Never arm a mutant, injected fault, or disabled guard in a tree that auto-commits — parameterize the tool under test by PATH and mutate a COPY, asserting the tracked file unchanged in the same script — `[[never-arm-a-fault-in-an-auto-syncing-tree]]`.
- On any API or tool error, route around it; never abandon the task — `[[feedback-never-give-up-on-api-errors]]`.
- Never report background work as just "still running" — stream a progress bar (counter, elapsed, rate-derived ETA, explicit working/STALLED) via `~/.claude/bin/progwatch` under `Monitor`, and design every long job around a countable artifact so progress is observable from outside — `[[report-background-progress-with-eta]]`.
- Age any session-liveness probe from the last ASSISTANT TURN, never the transcript file's mtime — foreign writes (notifications, a peer's kill of an unrelated process) refresh mtime, so a dead seat reads LIVE forever; and FORCE THE CLOCK in the control, because a control asserting against live fleet state passes by accident — `[[liveness-ages-from-the-last-turn-not-file-mtime]]`.
- Arm a persistent stall-watchdog at every background-agent dispatch and AUTO-REVIVE on stall (~20 min with no writes and no worker processes → SendMessage nudge; a nudge is safe when nothing is stalled) — `[[worker-liveness-must-reflect-progress]]`.
- Read a machine-bound id BYTE-EXACT (`od -c`) before matching on it: an id scraped from COLOURISED stdout matches nothing, so a watchdog reads a live successor as `gone` and stands down. `handoff.sh`'s own two capture sites were fixed 2026-08-25 (`_strip_csi` in front of both), so this is now a general rule about capture sites rather than an open bug there — repair a poisoned record by append, re-arm with a fresh `--watch-gen`, and prove it with a control — `[[handoff-session-id-ansi-poisoning]]`.
- Read and classify a tool error before routing around it: one naming a replacement is a redirect, not a disable; reproduce any "X is broken" claim yourself, fix the registry not the prompt, and correct the record where the misdiagnosis was written — `[[read-the-tool-error-before-routing-around]]`.
- When the user hands work to a Codex session SHE drives, deliver ONE fenced copy-paste prompt block with nothing inside the fence but the prompt — self-contained, absolute paths, constraints inlined (Codex sees none of our conversation and reads `AGENTS.md`, never `CLAUDE.md`), deliverable and output format named, tier/effort stated OUTSIDE the block; never hand her a `run-codex.sh` command line — `[[codex-handoffs-ship-as-a-pasteable-prompt]]`.
- Run `codex exec` only through the vendored watchdogged launcher `~/dotfiles/claude/skills/codex-converge/run-codex.sh` (autonomous arc only) — `[[codex-exec-hang-watchdog]]`.
- Set the Codex tier AND the effort on every call — Sol defaults to `low`, there is no `--effort` flag, and tier/profile availability is PER-MACHINE, so verify the tier from the run-log banner rather than the flag you passed — `[[codex-model-tiers-and-effort-routing]]`.
- Codex may IMPLEMENT mechanical plan tasks (`run-codex.sh --write`, linked worktree only), but whoever wrote a range never reviews it — `[[codex-may-implement-never-self-review]]`.
- Enforce review output with `--output-schema`, and check caller-side what the schema cannot express (uniqueness, ranges, whether the manifest names the right files) — `[[openai-structured-output-schema-limits]]`.
- Run the Codex↔Claude fact-check convergence loop on research/report deliverables, adjudicating every disputed fact against primary sources — `[[codex-claude-convergence]]`.
- Resolve HEAD when dispatching a commit review and re-check it when the verdict lands; an amend mid-review voids the verdict — `[[review-the-commit-that-is-checked-out]]`.
- Fetch and read the suspect file at `origin/HEAD` BEFORE diagnosing or building, and for a live symptom check merged-but-undeployed first — `[[fetch-before-you-diagnose]]`.
- Where a push auto-deploys, merging IS restarting production — so treat that as a GATE LIST, never as a reason to hold a green merge: check for in-flight work AND for other actors inside your window, enforce the freeze mechanically (built from what those actors can actually operate), and when every gate passes, MERGE without asking — an unmerged green PR is its own failure — `[[merging-is-restarting-production]]` · `[[merge-green-prs-without-asking]]`.
- Implement stated numeric/layout/timing rules exactly; unit-test them; verify the cited example — `[[feedback-spec-stated-rules-exactly]]`.
- When the product TELLS a user to do something ("reply STOP", "type DELETE"), test that exact string end-to-end, and check whether the mechanism has ever fired live — `[[test-the-mechanism-you-advertise]]`.
- When surfacing a backend gate in the UI, mirror its exact SCOPE (every enclosing condition and interceptor), not just its comparison; state the invariant in one line and share one predicate with the backend — `[[mirror-a-gate-at-its-exact-scope]]`.
- Pin the clock in any test of date/time-dependent behaviour, and write boundary tests to cross the boundary while mounted; a test mixing an injected clock with `Date.now()`-relative anchors EXPIRES on a computable date rather than flaking — derive that date, and say plainly whether you cured the instance or the class — `[[pin-the-clock-in-clock-dependent-tests]]`.
- A test asserting `elapsed < <constant>` measures the MACHINE, not the code — assert a RATIO against a calibration phase the same test already runs in-process, state the sensitivity you measured (not one you hope for), and enumerate the class by zeroing every ceiling so each prints its own elapsed time before deciding which to convert — `[[wall-clock-ceilings-measure-the-machine]]`.
- A test driving a child has TWO wall-clock budgets — the spawn's `timeout:` and the runner's per-test default (5000 ms in vitest/jest absent config) — and the MINIMUM fires, so a deliberate 60 s spawn ceiling under an inherited 5 s one is a ceiling NOBODY chose; DERIVE the outer from the inner (`TEST_BUDGET_MS = CHILD_TIMEOUT_MS + 30_000`) rather than writing a second literal, enumerate the class by AST transitively through file-local helpers (a file-level answer over-approximates 10×), and suspect this whenever a suite reddens in BATCHES with the runner's opaque timeout rather than the child's own output — the new files are the TRIGGER, not the cause — `[[the-effective-timeout-is-the-min-of-two-budgets]]`.
- Derive a cyclic symptom’s WINDOW before measuring, timestamp every observation, and record the window in the handoff — an out-of-window look reads as “no bug” — `[[reproduce-cyclic-symptoms-inside-their-window]]`.
- Fold every mockup or brainstorm critique into the spec and plan — `[[mockup-critiques-into-spec]]`.
- When a defect class recurs across review rounds at DIFFERENT sites, stop hunting instances: demand an enumeration of every site with a three-way classification and a reported count — `[[enumerate-recurring-defect-classes]]`.
- Keep the convergence loop SHORT without lowering the bar: after three consecutive rounds in one region, census-close it (derive the accepted/refused sets FROM THE CODE, pin both directions) and write in the scorecard that the next panel is the LAST for that region; overlap the micro-review (reads a committed sha) with Phase C (runs on a copy); arm mutants through `~/dotfiles/claude/skills/codex-converge/mutate.py` and one per-arc `make-prompts.py` instead of rewriting them each round; surface human-gated ship steps at the FIRST green (measured: rounds 3–6 of one validator review, 15→10→14→9→7→6 findings, all in one fold pipeline) — `[[convergence-loop-speed-rules]]`.
- When a reviewer names ONE instance of a defect, fix the whole class before calling it done: ask what the general form of the bug is and grep for every other site of that same shape, then pin the class with a test, not just the reported instance — `[[fix-the-class-not-the-reported-instance]]`.
- Earn "mutation-verified" per ITEM, never per round; when a record's claim turns out overstated, correct it in place and say it was overstated — `[[verification-claims-are-earned-per-item]]`.
- A result that beats the pre-registered expectation by a wide margin — OR two numbers that disagree about one artifact — is a DEFECT SIGNAL first: prove both sides are the same statistic under the same RULE from the same artifact (print each side's definition; read both from one result object), never a summary-file number against a per-run one; when counts disagree the artifact is rarely the variable, so run the gap down to named items before reporting either, validate any walker on the figure already agreed before trusting it on the unknown one, and publish the rule with the count — a bare count cannot be re-derived, only believed (measured: three passes over an UNCHANGED file gave 33/49, 35/54, 35/56, and the round that "corrected" the original was the one in error) A stated counting rule is itself an unchecked artifact — evaluate the predicate against what it claims to describe, and name which of its choices the agreement does NOT test (two readings agreeing because they share a silent assumption are one test, not two). — `[[surprising-result-check-metric-identity]]`.
- Before nudging or re-dispatching a seat, READ its `detail` — `failed` is two facts (cap-killed is revivable, retired-by-decision never is) and a SendMessage wave wakes a session regardless of `state.json`, handing it stale live instructions; preserve the prior `detail`, and attribute a revival by ORDERING rather than by re-reading state — `[[a-revival-wave-must-read-detail-before-nudging]]`.
- Continue/revive/re-dispatch every session on **Fable** (`claude-fable-5[1m]`) unless Fable's own limit is spent — established by a THROWAWAY PROBE dispatch that failed turn 1 just now, never inferred from corpses in a window — or it died on the turn-1 safeguard — `opus[1m]` is the fallback, not the default; it is already handoff.sh's default, so do not hand-pass a tier to defeat it — but that default is DEAD CODE inside a bg seat, whose env exports `CLAUDE_HANDOFF_MODEL` and hands every seat it dispatches the parent's tier, so read the tier off the CHILD's `respawnFlags` before reporting it — `[[continued-sessions-default-to-fable]]`.
- Model-route Lavish annotation replies by complexity (Haiku/Sonnet/Opus), label the model used, and honor her override — `[[lavish-triage-model-routing]]`.
- When building any data-driven UI, apply the product defaults and verify on the live page — `[[data-product-ui-defaults]]`.
- After a batch of corrections, codify the recurring classes as durable rules without being asked — `[[extract-learnings-proactively]]`.
- Never conclude a step succeeded from a status flag, log line, or assumption — verify against the artifact it should have produced; and never dispute someone's COUNT without re-running THEIR rule, because a count is not a measurement until its rule is stated (measured: three passes over one byte-identical artifact gave 33, 35 and 35 files on three different definitions) — "does not reproduce" is a claim about their rule, while "my rule differs" is all you have until you have run it — `[[verify-claims-against-artifacts]]`.
- Counting a set is NOT classifying it — never let a measured count carry an unmeasured KIND, because the rigorous table next to the guess lends it the table's authority: open the members (all of them, or the largest first — the distribution is skewed and the biggest one breaks the claim), put the shape in a COLUMN so an unread member cannot hide inside prose, and re-derive any estimate the classification fed (measured: 420 conflicted lines called "all just registry rows, careful work not hard work" were 15% that, and the largest — 62% of the lines — was a PORT onto a file main had replaced; `git merge-tree --write-tree` + `git cat-file -p <tree>:<path>` dumps every conflict hunk with no worktree, so cost is never the excuse) — `[[counting-a-set-is-not-classifying-it]]`.
- Write every CLI flag as `--flag=value` and put positionals FIRST: a flag whose value is OPTIONAL eats the next positional as its value, and when that value is an output path it OVERWRITES the file you meant to inspect, silently and with exit 0 (measured: `vitest list --json <testfile>` replaced a 17KB test file with a 624KB listing, and the next three probes all read the JSON) — `[[an-optional-value-flag-eats-the-next-positional]]`.
- Run every verification under the CONSUMER's exact condition (cwd, repo-or-not, env) — a check run where a fallback exists tests the fallback, not the artifact: in-repo `git apply --check` resolves malformed headers via the index line that a non-repo scratch refuses — `[[verify-in-the-consumers-condition]]`.
- Where parallel sessions share one `.git`, write → `git add` IMMEDIATELY → then run anything, and verify each commit with `git show HEAD:<file>`; a commit that captured reverted content describes changes it does not contain — `[[stage-immediately-verify-commits-from-the-object]]`.
- Before concluding something never happened, name the write site a positive case would produce and confirm your probe reads THAT artifact; reproduce someone else's absence-proof before amplifying it — and for any check that reduces to a boolean, run it against a CONTROL that forces the opposite answer, distrusting hardest the probe you wrote yourself ninety seconds ago to confirm what you expected — `[[absence-needs-a-probe-that-could-see-presence]]`.
- A control must reproduce the failing probe's SHAPE, not merely its components — testing the pieces in isolation is a second measurement that happens to be green, never a control; and NEVER read an exit status off a `;`-joined line, whose status is its LAST component's (`cmd > log 2>&1; echo "EXIT=$?"; tail log` reports `tail`'s 0, and the harness reports that for the whole line) — capture `ec=$?` immediately, and re-read your own probe's FULL output before writing up a striking result, because the refutation is usually already in it (measured: I filed a CI-integrity lane over a suite that had printed `EXIT=1` on line 1, directly above the table I was quoting, while both controls tested BARE commands) — `[[a-control-must-match-the-probes-shape]]`.
- Control a "has it finished?" predicate against the tool's REAL captured output, never a hand-written success case: `gh pr checks` DROPS the pending clause when nothing is pending (`"22 passed, 0 failed, 22 total"`), so `*", 0 pending,"*` never fires and the loop reports TIMEOUT twenty minutes after green — while its predecessor `*"0 pending"*` matched inside `20 pending` and reported SETTLED on a running build; and the rollup itself LAGS, so even the structural `all(.bucket != "pending")` this rule used to recommend is FAIL-OPEN — measured 2026-09-01: `pending: 0 of 1` while the per-commit check-runs API showed 4 checks with 3 still queued/running, on a run `cancel-in-progress` had already cancelled, and a watcher called it SETTLED after 630s. A settle detector must require the DERIVED expected set of jobs to be PRESENT and successful, read per-commit not per-PR, and fail CLOSED; run `~/.claude/bin/ci-green.sh <sha> [base-ref]` (tested by `~/dotfiles/claude/bin/ci-green.test.sh`) instead of writing another one — `[[control-a-settle-detector-on-captured-output]]`.
- Prove a completeness guard CAN PASS, not just that it can fail — evaluate both sides of any `set(X) == <hand-named list>` assertion against the real artifact, because an unsatisfiable closure gets widened by hand to go green and hides the member it existed to catch; replace restatement with a DERIVED set asserted both directions, and state the bound the derivation leaves open — `[[a-guard-must-be-satisfiable-not-just-failable]]`.
- A guard predicate that tests for a MENTION ("the enclosing function names `stripAnsi`") is NOT a test that the thing was applied — it passes on the half-done fix it exists to catch; go structural (parse and walk the value's path), derive the site list from `git ls-files` with the sweep's BOUND written next to the assertion, and settle which predicate you actually wrote with a PARTIALLY-broken mutant on a COPY (a fully broken one fails both, so it proves nothing) — `[[a-mention-is-not-a-property]]`.
- Never retract a finding because a re-read shows the artifact now correct — that is equally "you were right and someone fixed it"; settle it by ORDERING (your claim's timestamp vs the artifact's change time, plus the author's account), and derive a stamp from mtime ONLY on a sole-writer artifact — on a shared one mtime is someone else's write, so stamp from your own transcript and say which — `[[re-read-cannot-tell-wrong-from-acted-on]]`.
- Before any mutating step, re-validate state AT ACT TIME and anchor selections by stable identity, never by index into data another process can rewrite — but fresh ≠ informed: ask what stage turns the real fact into the row you re-read and whether it has run, because no re-check closes a gap that ingestion has not yet filled — `[[act-on-fresh-state-anchor-by-identity]]`.
- One enum value per meaning; never overload a status flag across distinct outcomes — `[[unambiguous-status-and-logs]]`.
- Before running any enumeration or sweep against a live box — INCLUDING a "dry run", including one your own runbook calls safe — read the query it actually runs, count first, and bound it in the engine not in the language: `--dry-run` promises no WRITES and promises nothing about memory, CPU or locks — `[[dry-run-bounds-writes-not-resources]]`.
- Add a resource-constrained scale test for any path whose memory/time scales with input — `[[scale-test-large-data-paths]]`.
- Build fixtures so the WRONG implementation would give a different answer — the PRODUCTION index set for plan assertions (assert the index by name plus the wrong one's absence), and never a degenerate point (n=1, the value 1, 0, identical items) for a numeric one; assert exact values over inequalities, since an assertion is only worth the alternatives the fixture makes reachable — `[[plan-assertions-need-reachable-alternatives]]`.

- Test migrations through the REAL boot path (the actual open/boot entrypoint) against a legacy-shaped DB file, never by hand-seeding a fixture and calling migrate() directly — a bootstrap statement that runs before the migrator may only reference shapes present in EVERY historical version — `[[test-migrations-through-real-boot-path]]`.
- Reconcile every aggregate against the raw rows it summarizes, with a test on the invariant not the rendered string — `[[reconcile-aggregates-against-raw-rows]]`.
- Adjudicate reviewer disputes in the contract (explicit spec line + pinning test), never prompt-side — `[[adjudicate-review-disputes-in-the-contract]]`.
- When a generator changes, re-render the copies already persisted for human approval at the REVIEW surface, never at the send point — `[[persisted-drafts-need-rerender-at-review]]`.
- Pin a CI/deploy run by the commit YOU pushed (never "the latest run"), and confirm the deployed artifact carries your change rather than trusting the green tick — `[[watch-the-run-you-triggered]]`.
- For conditionally assembled text, assert the complete happy-path output byte-for-byte plus the absence of the conditional clauses — `[[assert-complete-message-not-substring]]`.
- A bug found mid-run of an autonomous research round is a stop-the-line event: halt launches, report blast radius, let the user decide — `[[pause-rounds-on-bug-discovery]]`.
- Gate any unattended push to a shared remote on the actual diff stats, never the commit message — `[[verify-unattended-pushes-against-diff]]`.
- Wire scheduler completion mail (you@example.edu, END,FAIL) into every batch job expected to run ≥ 1 h — `[[long-job-completion-email]]`.

- A staged runbook shared across sessions is claimed at FIRE TIME: re-verify no sibling session owns it after every gap (suspend/resume, retry, a watchdog re-fire), and never point two runs at the same artifact paths — `[[shared-runbooks-reclaim-ownership-at-fire-time]]`.
- In autonomous research operation, act on evidence-backed scope/panel/recipe decisions — and LAUNCH any run pre-specified in a reviewed, committed runbook within its stated envelope (partition, wall-time, tier) — with a written decision record and post-hoc notification; ask only for new spend beyond the envelope or reinterpretation of already-reported results — `[[operator-delegation-evidence-backed-research-decisions]]`.
- Re-measure any fix that changes WHAT an expression READS against **BASE**, never against the head it is fixing — a uniform one-step drift (a counter read pre- vs post-increment) is invisible head-to-head, invisible at a clamped ladder's ENDS (a floor swallows the bottom rungs, a cap the top) and invisible to shape-only assertions; pin the schedule in the unit the regression is measured in, freeze BASE's formula as a LITERAL in the test, assert the intended delta as a NUMBER, and derive the worst case as arithmetic over the domain rather than reading one fixture's total — a total quoted as a delta is the same overstatement one level up (measured: a `+ 1` added to keep an argument "1-based" cost +30.5s of mandatory sleep and survived two review rounds) — `[[review-each-fix-against-base-not-the-previous-head]]`.
- When a fix round moves HEAD off the reviewed sha, close the "head merged = head reviewed" gate by MEASURING executable identity (strip comments/blanks, compare hashes, and control the comparator with a one-token mutant), never by buying another review round — the gate fails by construction after every fix, so a review to close it just moves it again; classify the diff and prove the PRODUCTION class empty, and remember CI green rode along with all seven defects — `[[close-the-reviewed-head-gate-by-measuring-identity]]`.
- NEVER block a green PR on the user's approval — merge whenever mechanically safe (checks green on the current head, freeze CLEAR, no in-flight deploy/box work, no conflict), then watch the deploy pinned by YOUR merge SHA; "not mechanically safe" means fix or wait, not ask — `[[merge-green-prs-without-asking]]`.

- When a mutant SURVIVES, ask whether any outcome test could see the difference before calling the test weak; if a tolerant search or default makes the property unobservable, pin its INTENT instead — and measure the invariant across the population before authoring the guard — `[[a-surviving-mutant-may-mean-the-property-is-unobservable]]`.
- Recoverable is not unused: before deleting a mirrored/regenerable artifact, enumerate its DEPENDENTS (symlink farms, path config) and assert the dangling-link count is unchanged in the same script that deletes — `[[recoverable-is-not-unused]]`.
- The minimum replay archive is checkpoint + dataset + exact code pinned by COMMIT (a content hash is an identity, not a pointer); regenerate predictions on the SAME device class before comparing numbers — `[[minimum-replay-archive]]`.
- A resolving arXiv ID/DOI is not verification: fetch the record, check title + authors + the claimed mechanism, and build bibliographies from machine-fetched metadata with caller-side key/year/duplicate checks — `[[verify-citations-by-fetching-the-id]]`.
- Give any agent that MUTATES the tree its own worktree (`isolation: "worktree"`), commit with `-o <paths>` while siblings are live, and before calling a suite flaky ask what else was touching the tree in that window — including YOUR OWN mutation-test loop, which in a repo with content-hashed code identity fails the identity-dependent tests specifically — `[[isolate-agents-that-mutate-the-tree]]`.
- A gate may not read its deciding flag from the artifact it gates: name the value's WRITER, require it to resolve in a source the gated party does not author, and refuse outright any flag nothing computes — `[[a-gate-may-not-read-its-verdict-from-the-gated-party]]`.
- Never spend extra-usage credits or usage-based overage without explicit PER-ACTION permission — this binds the DEFAULT workflow's burn RATE (model tier, fan-out width, session length), not just rogue loops; credits engage silently, so state the tier and width BEFORE a fan-out and prefer one-shot checks over model-side polling — `[[no-extra-cash-without-permission]]`.
- Before spending compute to (re)generate a baseline/dataset a collaborator may already own, ASK the user first — off-repo runs are invisible to any local search, so "no checkpoint on this box" proves nothing — `[[ask-before-regenerating-a-collaborators-artifact]]`.
- Extract values from data files via sandboxed execution rather than full Reads, read only the span you will edit, batch pre-authorized step chains into one turn, derive once and persist the result WITH its pointer instead of recomputing it, and check a guard BEFORE authoring against it — `[[reduce-token-burn]]`.
- When vendoring code, vendor every input it resolves by SEARCH PATH too, pin each by hash, and make an unresolvable one raise — never tolerate absence, since a foreign file that merely exists hides the fall-through completely — `[[vendor-what-the-code-searches-for]]`.
- When a delegate waits on an external artifact (codex verdict, job output), use a harness-tracked blocking wait AND re-check the artifact on every wake before arming a new one; detached watchers and completion notifications both fail silently — `[[delegate-waits-must-be-harness-tracked]]`.
- When a review's finding rate goes FLAT, enumerate the findings by subsystem and ask what each subsystem is still FOR before ordering a rewrite — a flat rate often means a region outlived its purpose, and quarantine beats polishing dead code — `[[codex-parallel-lenses-beat-serial-rounds]]`.
- End every response that DISPATCHED work to another session with the copy-paste command to OPEN it, last thing before the state line — the two forms take DIFFERENT ids for the same seat — `claude attach <8-hex JOB id>` (the `~/.claude/jobs/<id>/` dir name; `attach` resolves jobs so a full UUID fails, and no `--` before it) for a live seat, `claude --resume <full session UUID>` for a finished one, `fleet <8-hex>` for a read-only tail; derive both from the job dir and check the id is byte-clean (`od -c`), since handoff.sh records carry ANSI-poisoned ids — `[[end-a-handoff-with-the-open-command]]`.
- A gitignored doc store does NOT travel with a branch into a fresh worktree — so a charge under `.superpowers/` (or any ignored path) is ABSENT at the seat you dispatched: write the path ABSOLUTE in the handoff, provision the store, and verify the read from the CONSUMER's cwd before dispatch (measured: an implementer burned ten tool calls hunting a 13,949-byte charge, and the alternative outcome is silently improvising eleven fixes); symlink the LEAF inside a real ignored parent, never the ignored root itself, because a trailing-slash ignore pattern matches directories only and git sees a symlink as an untracked FILE — `[[a-gitignored-doc-store-does-not-reach-a-fresh-worktree]]`.
- Every handoff / `claude --bg` successor boots in `bypassPermissions` — `handoff.sh` now DEFAULTS `PMODE` to it (the `PMODE=` default in `hooks/handoff.sh`'s option-parse block — cited by symbol, not line, because the line moves; pinned by AB5/AB6), so do not hand-pass a mode that defeats it; pass `--permission-mode` yourself only where no launcher supplies it (a direct `claude --bg`) or to give a seat `auto`/`manual` deliberately — the PROMPTING class parks an unattended seat forever on a tool-approval prompt that no `SendMessage` can drain — `[[handoff-dispatch-in-bypass-permissions]]`.
- Never write "I DROP the job" in a handoff doc before you actually have — write the CONDITION and name it; authority transfers only on an explicit two-sided exchange, and a contested seat is settled by two transcript-size samples ~50s apart, never by a document or a `ListAgents` row, with NOBODY touching the irreversible step until it is settled — `[[a-handoff-doc-must-not-assert-a-drop-it-has-not-made]]`.
- Before arming any polling loop, READ what its predicate does — a watch loop multiplies the predicate's side effects by its iteration count (a hold `node`-ing a gate whose line 128 `git fetch`es = ~127 prohibited fetches), so hash the predicate instead of executing it, pin a witness artifact before and after, and treat a script's own "READ-ONLY" / "cannot orphan" comment as a claim rather than evidence — `[[a-poll-loop-inherits-its-predicate]]`.

- A stand-down is not complete until you sweep `ps`, not `state.json` — shell-side watchers orphan to `ppid=1` and outlive every seat, and an armed `handoff.sh --watch` on an hours-old `state=launching` record is still dispatching; kill the token igniters (armed dispatchers, `--agent-reply` polls) first, and never write a hold as `until pgrep -f <pat>` because the waiter matches itself — `[[a-standdown-must-disarm-the-shell-watchers]]`.
- A fleet guard is a SNAPSHOT, not a latch — `DO-NOT-REVIVE` lives in the `state.json` the guarded seat itself rewrites, so any wake erases it and reverts `detail` to stale text; re-measure counts instead of carrying them forward, expect retiring a seat to WAKE its supervisor via the TERMINAL alert, and remember the durable half is the process kill, never the marker — `[[a-state-guard-is-a-snapshot-not-a-latch]]`.
- Fleet seats obey the BURN BUDGET: plumbing (relay/watch/hold/read) dispatches on Sonnet, a hold is a shell-side zero-token watcher never a model-side poll, a handoff doc is a READ SURFACE not a log (measured: cache-read is 97.5% of all tokens and 67% of cost, and the biggest text reads in the corpus are handoff docs at up to 506,884 B ≈ 126,721 tokens — more than a healthy session's ENTIRE 118k context; cut a capped brief with `scripts/fleet/handoff-brief.py` and archive the history), and every handoff RETIRES its predecessor with verification — `[[fleet-burn-budget]]`.

- Never bind a LATCHING or one-shot resource (a latch, `dispose()`, `abort()`, a closed pool) to a bare React effect cleanup — StrictMode's setup→cleanup→setup kills the one instance the component will ever have, before its first interaction, so bind through a hook whose SETUP restores what its cleanup tore down and pin it with an import census; every unit test that mounts WITHOUT `<StrictMode>` is blind to this class, so mount the pinning test under it and keep the hand-rolled version as an executable positive control (measured: 22 e2e failures across 12 spec files that 3051 unit tests could not see) — `[[strictmode-latches-a-dispose-on-cleanup-resource]]`.

## Memory

- A learning is **global** if it passes this test: "Would this help me in an unrelated project next week, independent of any single repo?" If yes, it is who the user is, a universal working preference, a tool/platform fact, or a generalizable lesson. Project-technical facts stay **local** even when the pattern is interesting — file the generalization, not the instance.
- **Routing.** A *behavioral directive* → write the body to `memories/global/` AND add a one-line imperative to the `## Working directives` section above. A *pure fact* → write the body to `memories/global/` with an index line only.
- Global memories live in `memories/global/` (flat namespace, globally-unique descriptive slugs). The `sync-memories.sh` Stop hook routes any `scope: global` memory there automatically; the `inject-global-memory.mjs` SessionStart hook loads the `memories/global/MEMORY.md` index into every project. Project-local memory overrides global defaults on project-specific constraints.
- Leave per-project state memories untagged so they stay local.
- Keep memories distilled — global AND project-local. When updating a memory, fold the correction into the rule and rewrite in place; never append dated "violated again" logs or restatements. One compact why per memory; index lines stay one line per memory (detail lives in the body, the index is loaded every session).
